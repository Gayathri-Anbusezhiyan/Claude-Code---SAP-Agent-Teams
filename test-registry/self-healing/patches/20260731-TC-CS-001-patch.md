# Patch: TC-CS-001 — 2026-07-31

## Failure Summary
- TC ID        : TC-CS-001
- Story        : CS-2
- Error Type   : LOCATOR_FAILURE
- Failing At   : submitPurchaseOrder() — ORDER_BUTTON
- Error Message: strict mode violation: getByRole('button', { name: 'Order' }) resolved to 2 elements

## Root Cause
Role-based locator `getByRole('button', { name: 'Order', description: 'Default Action' })` resolved to 2 elements in the DOM:
1. **Shell page title button** — `<div role="button" aria-label="Purchase Order">` (page header)
2. **Footer Order button** — `<button aria-describedby="__text18">` (actual target)

Despite including the `description: 'Default Action'` parameter, Playwright's strict mode in the test runner is more aggressive than in MCP execution and continues to match both elements.

## Fix Applied

### File: automation/pages/mm/purchase-order/purchase-order.page.js
- **Method**: `submitPurchaseOrder()` (lines 364-372)
- **Changed**: Direct locator call from `getPlaywrightLocator(this.page, LOCATORS.FOOTER.ORDER_BUTTON)` to `this.page.locator("button:has-text('Order')")`
- **Old**: Role-based selector via helper function
- **New**: CSS text selector `button:has-text('Order')` — unambiguous and reliable

### Rationale
- CSS text selector confirmed reliable in exploration data (step 22: PASS)
- Exploration fallback strategy explicitly recommends this selector
- Project memory confirms: "correct selector for Order button is `locator('button:has-text(\"Order\")')`"
- Avoids ambiguity with shell title button which also has role="button"
