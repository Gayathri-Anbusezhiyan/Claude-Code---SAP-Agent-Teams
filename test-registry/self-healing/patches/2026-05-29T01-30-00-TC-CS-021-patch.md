## Problem Summary

Test execution failed with `TIMEOUT_ERROR` at Step 7 (open search app navigation):

```
Error: Test timeout of 120000ms exceeded.
Locator.waitFor: getByRole('button', { name: 'Open Search' }) not visible after 120s
Location: automation/pages/mm/purchase-order/purchase-order.page.js:130 (openSearch method)
```

### Root Cause

The automation script uses `getByRole('button', { name: 'Open Search' })` to locate the SAP Fiori shell bar search button. This locator strategy **does NOT match** the actual element in the SAP UI because:

- **Script expects:** role=button with accessible name "Open Search" (via aria-label or implicit text)
- **SAP renders:** `<button title="Open Search">` — a button with HTML title attribute, NOT an accessible name
- **Playwright's getByRole():** Uses accessibility tree, which does NOT expose HTML title as accessible name

### Infrastructure Classification

- **Type:** AUTOMATION_BUG (locator strategy issue in script, not SAP behavior issue)
- **Root Cause:** Mismatch between SAP UI5 implementation (title attribute) and Playwright accessibility-tree-based locator
- **Applicability:** Affects all test cases using PurchaseOrderPage.openSearch() method (all MM Purchase Order tests)

---

## Solution Applied

### File: `automation/pages/mm/purchase-order/purchase-order.page.js`

**Line:** ~125-133 (openSearch method)

**Change:**

```javascript
// BEFORE (BROKEN):
async openSearch() {
  await this.page.waitForLoadState('networkidle', { timeout: 60000 }).catch(() => {});
  const searchBtn = this.page.getByRole('button', { name: 'Open Search' });  // ❌ DOES NOT MATCH
  await searchBtn.waitFor({ state: 'visible', timeout: 90000 });
  await searchBtn.click();
  await this.page.waitForTimeout(500);
}

// AFTER (FIXED):
async openSearch() {
  await this.page.waitForLoadState('domcontentloaded', { timeout: 60000 }).catch(() => {});
  const searchBtn = this.page.locator('[title="Open Search"]');  // ✅ MATCHES SAP UI5 HTML
  await searchBtn.waitFor({ state: 'visible', timeout: 90000 });
  await searchBtn.click();
  await this.page.waitForTimeout(500);
}
```

### Why This Fix Works

1. **CSS attribute selector `[title="Open Search"]`** directly targets the HTML title attribute
2. **More stable than role-based locators** for SAP UI5 shell bar components
3. **Verified via Phase 5 MCP re-execution** in headed mode (browser visible)
4. **No dependencies on accessibility tree** interpretation

### Locator Strategy Comparison

| Strategy | Used By | Result | Notes |
|----------|---------|--------|-------|
| `getByRole('button', { name: 'Open Search' })` | Phase 4 (original) | ❌ FAIL (120s timeout) | Accessibility tree doesn't expose title as name |
| `[title="Open Search"]` | Phase 5 (this patch) | ✅ PASS | Direct HTML match, reliable |
| `button:has-text("Open Search")` | Alternative | ⚠️ Unreliable | HTML title ≠ text content |

## Notes for Future Maintenance

### SAP UI5 Shell Bar Locators

If other shell bar elements need locating, prefer CSS/title-based selectors over getByRole:

```javascript
// ✅ Recommended (works with SAP UI5 shell):
page.locator('[title="Element Name"]')
page.locator('button[aria-label="Element Name"]')  // if aria-label is used

// ❌ Problematic (SAP UI5 uses title, not accessible name):
page.getByRole('button', { name: 'Element Name' })
```

### Phase 3 Findings Contradiction

Phase 3 comment stated: "Phase 3a MCP confirmed button uses role=button name='Open Search'". This was **incorrect**. Phase 5 re-execution in headed mode conclusively showed the button does NOT expose "Open Search" as an accessible name via the accessibility tree. Likely Phase 3a notes were based on HTML inspection rather than actual Playwright locator testing.
