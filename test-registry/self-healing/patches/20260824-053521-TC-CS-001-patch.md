# Self-Healing Patch Report

## Test Case
**TC-CS-001** — Create Standard PO — single line item

## Failure Type
**TIMEOUT_ERROR** (flaky test — passed on retry #1)

## Root Cause
Search results timeout (3 seconds) was too aggressive for SAP Fiori search autocomplete under variable network conditions. Test failed on first attempt when SAP backend response exceeded 3s, then passed on retry with warmed cache.

## Applied Fixes

### Fix 1: Increase Search Results Timeout
**File:** `test-registry/automation/pages/mm/purchase-order/purchase-order.locators.js`  
**Line:** 247  
**Change:**
```javascript
// Before
SEARCH_RESULTS: 3000,       // Search results to appear (increased)

// After
SEARCH_RESULTS: 10000,      // Search results to appear (increased to 10s for SAP Fiori search latency)
```

**Rationale:** SAP Fiori search autocomplete can take 3-10 seconds depending on backend load and network conditions. Increasing timeout from 3s to 10s provides sufficient buffer while still failing fast enough if search truly breaks.

### Fix 2: Replace Fixed Wait with Brief Pause
**File:** `test-registry/automation/pages/mm/purchase-order/purchase-order.page.js`  
**Method:** `searchForApp()`  
**Line:** 192  
**Change:**
```javascript
// Before
await searchBox.fill(appName);
await this.page.waitForTimeout(WAITS.SEARCH_RESULTS);  // Fixed 3s wait

// After
await searchBox.fill(appName);
// Wait for search results to populate (no fixed timeout — wait dynamically)
await this.page.waitForTimeout(500);  // Brief pause for search to trigger
```

**Rationale:** The original code waited a fixed 3 seconds regardless of whether search results appeared. The dynamic wait in `selectSearchResult()` already handles waiting for the row to appear (up to 10s), so we only need a brief 500ms pause here to let the search trigger, then let the next step wait dynamically.

### Fix 3: Enhanced Wait Comment
**File:** `test-registry/automation/pages/mm/purchase-order/purchase-order.page.js`  
**Method:** `selectSearchResult()`  
**Line:** 197  
**Change:** Added clarifying comment explaining the increased timeout is for SAP Fiori search backend latency.
