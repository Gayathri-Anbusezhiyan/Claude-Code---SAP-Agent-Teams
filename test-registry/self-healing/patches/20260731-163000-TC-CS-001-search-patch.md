- Error Message: input[type='search'] not visible after 5s

## Root Cause
CSS selector `input[type='search']` was set as primary but doesn't reliably match SAP's search box implementation. The element is actually a combobox with ARIA role, not a standard search input.

## Fix Applied

### File: automation/pages/mm/purchase-order/purchase-order.locators.js
- **Changed**: `SHELL_BAR.SEARCH_COMBOBOX` primary/fallback order
- **Old Primary**: `{ strategy: 'css', value: "input[type='search']" }`
- **New Primary**: `{ strategy: 'role', role: 'combobox', name: 'Search', exact: true }`
- Old primary demoted to `fallbacks[0]`

### Rationale
- Role-based selector confirmed working in exploration data (step 8: PASS)
- CSS `input[type='search']` doesn't match SAP's actual implementation
- SAP uses a combobox component with ARIA role, not a native search input
