# Patch: TC-CS-001 — 2026-05-29 18:38:40

## Failure Summary
- TC ID        : TC-CS-001
- Story        : CS-2
- Error Type   : TIMEOUT_ERROR (incorrect wait strategy)
- Failing At   : openSearch() — line 148
- Error Message: "TimeoutError: locator.waitFor: Timeout 15000ms exceeded waiting for getByRole('button', { name: 'Open Search' }) to be visible"

## Root Cause

SAP Fiori Launchpad uses **progressive rendering** for the shell bar. After login:
1. **Phase 1 (immediate)**: Essential navigation elements render (Open Menu, SAP Logo, Home, Profile)
2. **Phase 2 (2-3 seconds later)**: Action buttons render asynchronously (Open Search, Joule, Open Help, Notifications)

The previous patch (TC-CS-021, applied 2026-05-29 18:29:29) incorrectly assumed clicking "Open Menu" triggers button rendering. This was a **false correlation** — during manual MCP re-execution, the delay between actions gave the shell bar time to render naturally. The "Open Menu" click was coincidental timing, not causal. Automated Playwright runs execute faster, exposing the flaw.

**Actual cause**: The script tried to click "Open Search" immediately after login, before Phase 2 rendering completed.

**Correct solution**: Simply wait for the button to appear (it renders automatically within 2-3 seconds). No prerequisite action needed.

## Fix Applied

### File: automation/pages/mm/purchase-order/purchase-order.page.js

**Change Type**: WAIT_UPDATE (removed flawed workaround, simplified wait strategy)

**Method Modified**: `openSearch()`

**Changes**:
1. **Removed**: Flawed "Open Menu" prerequisite logic (Steps 1-3)
2. **Simplified**: Direct wait for button visibility with 30-second timeout
3. **Timeout**: Increased from 15s to 30s (gives 10x the observed delay for reliability)
4. **Comment**: Updated to reflect correct understanding of SAP shell bar behavior

**Old Code (flawed)**:
```javascript
async openSearch() {
  await this.page.waitForLoadState('domcontentloaded', { timeout: 60000 }).catch(() => {});

  // Step 1: Check if "Open Search" button is already visible
  const searchBtn = this.page.getByRole('button', { name: 'Open Search' });
  const isSearchVisible = await searchBtn.isVisible().catch(() => false);

  if (!isSearchVisible) {
    // Step 2: Click "Open Menu" to trigger shell bar full render
    const openMenuBtn = this.page.getByTitle('Open Menu');
    await openMenuBtn.waitFor({ state: 'visible', timeout: 30000 });
    await openMenuBtn.click();
    await this.page.waitForTimeout(1000);

    // Step 3: Close the navigation menu
    await openMenuBtn.click();
    await this.page.waitForTimeout(500);
  }

  // Step 4: Now "Open Search" button should be visible
  await searchBtn.waitFor({ state: 'visible', timeout: 15000 });
  await searchBtn.click();
  await this.page.waitForTimeout(500);
}
```

**New Code (correct)**:
```javascript
async openSearch() {
  // SAP Fiori shell bar lazy-loads action buttons.
  // After login, "Open Search" button appears automatically within 2-3 seconds.
  await this.page.waitForLoadState('domcontentloaded', { timeout: 60000 }).catch(() => {});

  // Wait for shell bar to complete rendering (button appears automatically)
  const searchBtn = this.page.getByRole('button', { name: 'Open Search' });
  await searchBtn.waitFor({ state: 'visible', timeout: 30000 });
  await searchBtn.click();
  await this.page.waitForTimeout(500);
}
```

## Lessons Learned

1. **Correlation ≠ Causation**: During manual re-execution, actions are naturally slower (taking snapshots, analyzing results). This gave SAP shell bar time to render between steps. The "Open Menu" click appeared to work, but it was just good timing.

2. **Automated execution is faster**: Playwright runs actions with minimal delay. This exposes timing assumptions that worked during slow manual testing but fail in fast automated runs.

3. **Simplest solution is usually correct**: The correct fix is a simple wait with appropriate timeout. Complex workarounds often indicate misunderstanding of the root cause.

4. **Re-execute to verify timing**: When a patch fails, re-execute with timing observations (explicit waits at different intervals) to understand actual behavior, not assumed behavior.
