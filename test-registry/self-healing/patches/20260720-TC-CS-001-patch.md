# Patch: TC-CS-001 — 2026-07-20 07:30:00

## Failure Summary
- TC ID        : TC-CS-001
- Story        : CS-2
- Error Type   : LOCATOR_FAILURE
- Failing At   : clickCreate() — createPOButton
- Error Message: strict mode violation: getByRole('button', { name: 'Create' }) resolved to 2 elements

## Root Cause

The SAP Guided Tour appears non-deterministically after navigating to the Manage Purchase Orders app. When the tour is present, it creates a hotspot overlay element with `role="button"` and `aria-label="Create Purchase Order"`. The script's generic locator `getByRole('button', { name: 'Create' })` matches BOTH:
1. The actual "Create" button for creating a PO
2. The guided tour hotspot with "Create Purchase Order" label

During exploration (2026-07-08), the tour did NOT appear, so the locator was unambiguous and passed. During test runner execution (2026-07-20), the tour DID appear, causing the strict mode violation.

## Fix Applied

### File: [automation/pages/mm/purchase-order/purchase-order.page.js](automation/pages/mm/purchase-order/purchase-order.page.js)

**Change Type**: INTERACTION_UPDATE — Added proactive guided tour dismissal logic

**Method Modified**: `navigateToApp()`
- **Added**: Call to `dismissGuidedTour()` after app loads
- **Added**: New method `dismissGuidedTour()` that attempts to click "Leave Tour" button with 3s timeout
- **Logic**: Try-catch wrapped so script continues normally if tour is not present

**Lines Modified**:
- Line 80: Added `await this.dismissGuidedTour();` after app navigation
- Lines 85-95: Added new `dismissGuidedTour()` method

**Before patch:**
```javascript
async navigateToApp() {
  // ... navigation logic ...
  await this.page.waitForLoadState('domcontentloaded');
  await this.page.waitForTimeout(2000);
}
```

**After patch:**
```javascript
async navigateToApp() {
  // ... navigation logic ...
  await this.page.waitForLoadState('domcontentloaded');
  await this.page.waitForTimeout(2000);

  // PATCHED 2026-07-20: Dismiss SAP Guided Tour if present (non-deterministic)
  await this.dismissGuidedTour();
}

async dismissGuidedTour() {
  try {
    const leaveTourBtn = this.getLocator('leaveTourButton');
    await leaveTourBtn.click({ timeout: 3000 });
    await this.page.waitForTimeout(500);
  } catch (e) {
    // Tour not present — continue normally
  }
}
```

### Locator NOT Changed

The `createPOButton` locator in [automation/pages/mm/purchase-order/purchase-order.locators.js:51](automation/pages/mm/purchase-order/purchase-order.locators.js#L51) is **correct and unchanged**:
```javascript
createPOButton: {
  primary: { strategy: 'role', role: 'button', name: 'Create' }
}
```

The issue is environmental (guided tour presence), not the locator itself. After dismissing the tour, this locator works perfectly.

## Why This Approach?

**Alternative rejected**: Add `exact: true` to the Create button locator
- **Problem**: `exact: true` would require `{ name: 'Create', exact: true }` which still matches both elements (button text "Create" and aria-label "Create Purchase Order" both contain "Create")
- **Solution chosen**: Proactively remove the ambiguity by dismissing the tour before attempting to click Create

**Alternative rejected**: Filter by element type (exclude `div[role="button"]`)
- **Problem**: This would require a CSS fallback which is less resilient than the role-based locator
- **Solution chosen**: Keep the semantic role locator and remove the interference
