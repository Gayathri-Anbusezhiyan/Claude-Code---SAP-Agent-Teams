## Description

## Background

The Send for Review and Verification workflow ensures that quality documents undergo formal peer review before progressing beyond the Draft state. This story covers the workflow initiation phase where the Quality Doc SME locates a draft document and formally assigns it to a reviewer for evaluation.

## What This Story Covers

The Quality Doc SME authenticates to Veeva Vault QualityDocs, navigates to the Full Library, searches for and opens a document in Draft state ("Test1 for Workflow"), initiates the "Send for Review And Verification" workflow action, assigns a reviewer (Test_user01@partnersi-capgemini.com), and confirms the submission — causing the document to transition from Draft to In Review and a workflow task to be assigned to the designated reviewer.

## Roles

* **Primary actor:** Quality Doc SME — initiates the workflow and assigns the reviewer
* **Supporting roles:** None (reviewer becomes active in CS-13)

## Preconditions

* Document "Test1 for Workflow" exists in the system in Draft state
* Quality Doc SME account has valid credentials and appropriate role permissions
* Reviewer account exists and has Reviewer role permissions
* The "Send for Review And Verification" workflow action is configured and available

## Workflow Context

State before: Document "Test1 for Workflow" is in Draft state; no active workflow  
State after:  Document is in In Review state; workflow task assigned to reviewer

## Acceptance Criteria

### Happy Path

* \[RP-FUNC-001\] The Quality Doc SME can authenticate to Veeva Vault QualityDocs using role-specific credentials
* \[NAV-001\] After entering the application URL and submitting valid credentials, the user gains access to the QualityDocs module landing page
* \[RP-FUNC-002\] The Quality Doc SME can navigate from the QualityDocs landing page to the Full Library view
* \[NAV-002\] After clicking "Full Library" in the navigation, the Full Library document search interface is displayed
* \[RP-FUNC-003\] The Quality Doc SME can search for a document by name ("Test1 for Workflow") and see matching results
* \[NAV-003\] The Quality Doc SME can open the document from search results and the document detail page is displayed
* \[RP-FUNC-004\] The document detail page confirms the document is in Draft state
* \[RP-FUNC-005\] The Quality Doc SME can click the "Send for Review And Verification" user action on the Draft document
* \[NAV-004\] After clicking the workflow action, a workflow initiation dialog is displayed with a reviewer assignment field
* \[RP-FUNC-006\] The Quality Doc SME can select a reviewer from the reviewer assignment field
* \[RP-FUNC-009\] After submitting the workflow initiation, a workflow task is created and assigned to the designated reviewer
* \[AR-001\] After workflow submission, the document status transitions from Draft to In Review
* \[AR-002\] After workflow submission, the reviewer sees the assigned workflow task in their Home view task list
* \[RP-DATA-001\] The document status field displays "In Review" after the workflow is initiated

### Alternative Paths

* If the SME navigates directly to the QualityDocs URL with tab parameters, the Full Library may be accessible without additional navigation

### Validation and Error Cases

* \[GR-001\] The "Send for Review And Verification" action is disabled or hidden when the document is not in Draft state
* \[GR-002\] The workflow initiation dialog prevents submission when no reviewer is selected (reviewer field is mandatory)
* \[RP-ROLE-001\] Only users with the Quality Doc SME role can access and execute the "Send for Review And Verification" workflow action
* \[GR-006\] Only authenticated users with valid credentials can access the QualityDocs workflow functionality
* \[RP-NFR-003\] The system must enforce role-based access control — users without SME role cannot initiate the workflow
* \[RISK-003\] The system shall prevent workflow initiation on documents that are not in Draft state — HIGH severity risk mitigation
* \[RISK-004\] The system shall validate that the assigned reviewer account exists and has Reviewer role permissions before allowing workflow submission — HIGH severity risk mitigation

### Business Rules

* \[BR-001\] The "Send for Review And Verification" workflow can only be initiated on documents in Draft state
* \[BR-002\] A reviewer must be assigned when initiating the workflow (mandatory field)
* \[RP-BIZ-002\] The reviewer assignment field must contain a valid reviewer account before the system allows workflow submission

### Inferred / TBC Items

* Assumed: The system validates that a reviewer is selected before allowing workflow initiation (GAP-002)
* Assumed: Workflow task assignment triggers an immediate update in the assignee's task list (GAP-004)
